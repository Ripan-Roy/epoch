# Epoch v0.2.0-beta.11

Epoch beta.11 expands the bounded Redis, Kafka, and RabbitMQ compatibility
surface over Epoch's native replicated Cache, Stream, and Queue profiles. The
release adds transactional Redis operations, lossy Pub/Sub, durable Streams
groups, non-transactional Kafka idempotence, and durable AMQP topology with
named dead-letter routing.

This remains a private-beta evaluation release. The documented subset is
verified with exact released clients and a three-node recovery campaign, but it
does not claim complete broker compatibility or performance parity.

## Redis compatibility

- `MULTI`, `EXEC`, and `DISCARD` queue at most 128 commands and distinct keys,
  then apply supported writes atomically through one Cache revision.
- `WATCH` and `UNWATCH` use per-key versions and abort `EXEC` when a watched key
  changes. Queue-time errors produce `EXECABORT`; per-command execution errors
  remain ordered results.
- `SUBSCRIBE`, `PSUBSCRIBE`, publish, and unsubscribe provide bounded
  node-affine, at-most-once delivery with RESP2 and RESP3 push output.
- `XADD`, `XLEN`, `XRANGE`, `XREAD`, `XGROUP` create/destroy/set-ID,
  `XREADGROUP`, `XACK`, and `XPENDING` map to a durable provisioned Stream plus
  a bounded Cache-backed consumer-group ledger.
- Redis clients cannot access the reserved `__epoch:` compatibility metadata
  prefix directly, through watches, or through queued transactions.

## Kafka and RabbitMQ compatibility

- `InitProducerId` versions 0–5 initialize a bounded non-transactional Kafka
  producer. Contiguous per-partition sequence spans append atomically through
  Stream state-command v8; exact retry returns the original offset, while gaps,
  stale epochs, and conflicting replay are fenced.
- Existing Stream state-command v7 history remains readable. New idempotent
  batch commands are rejected if mislabeled as v7.
- Durable AMQP exchanges, bindings, and dead-letter declarations persist in a
  configured quorum-durable Cache and reload in an independent gateway process.
- A named dead-letter exchange must resolve to exactly the provisioned native
  Queue target. The Queue outbox preserves exchange/routing metadata and adds
  bounded coalesced `x-death` plus first/last-death fields.
- Passive exchange reopen follows released RabbitMQ client behavior without
  treating the empty passive-declare type as an active redeclaration.

## Upgrade and configuration

No Catalog, EPRS, Cache snapshot, Queue snapshot, or customer-data migration is
required. Existing Stream state-command v7 entries decode unchanged; new
idempotent producer batches use v8. Configure `--amqp-topology-cache` or
`EPOCH_COMPAT_AMQP_TOPOLOGY_CACHE` to a dedicated quorum-durable Cache, restrict
native administrative access to it, and retain the default no-eviction policy.

Redis Pub/Sub is intentionally process-local and does not survive gateway loss.
Clients that require durable subscriptions should use Redis Streams or Epoch's
native Event Bus. Cache eviction is operator-selected and deterministic; Epoch
does not automatically switch LRU/LFU/TTL/random policies based on workload.

## Beta limitations

- Redis Lua/functions, extended Streams trim/claim/multi-stream behavior,
  cluster mode, and TLS are unsupported. Pub/Sub is node-affine and lossy.
- Kafka transactions/control batches, cooperative/new consumer groups,
  simultaneous duplicate static-owner fencing, SASL, TLS, and broad admin APIs
  are unsupported.
- Arbitrary AMQP dead-letter fanout, server-named/auto-delete topology, general
  policies and field values, transactions, AMQP 1.0, TLS, and plugins are
  unsupported.
- Compatibility fuzzing, matched Redis/Kafka/RabbitMQ performance evidence,
  production SLOs, and protected beta.11 evidence remain release gates.
