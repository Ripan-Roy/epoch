# Epoch v0.2.0-beta.7

Epoch beta.7 adds a bounded production-observability layer across the Rust data
plane, Go control plane, compatibility gateway, operator, console, and official
Go, Java, and Python SDK contracts. Operators can scrape internal Prometheus
metrics, export distributed traces over OTLP/HTTP, and ask **Why slow?** for a
recent tenant/profile window without exposing customer resource names as metric
labels.

This remains a private-beta evaluation release. The diagnosis reports only
measured recent routing, replication, and storage evidence; it does not invent
causes, promise exhaustive telemetry, or replace workload-specific capacity and
loss-risk analysis.

## Published artifacts

The verified tag workflow publishes these exact multi-platform OCI manifests
for `linux/amd64` and `linux/arm64`:

- `ghcr.io/ripan-roy/epoch-node:v0.2.0-beta.7`
- `ghcr.io/ripan-roy/epoch-control:v0.2.0-beta.7`
- `ghcr.io/ripan-roy/epoch-operator:v0.2.0-beta.7`
- `ghcr.io/ripan-roy/epoch-cli:v0.2.0-beta.7`
- `ghcr.io/ripan-roy/epoch-compat:v0.2.0-beta.7`

Each exact-tag manifest is assembled from immutable native amd64 and arm64
digests, inspected as non-root, signed keylessly with Sigstore, and accompanied
by BuildKit/GitHub provenance, SPDX SBOM attestations, and ten platform-specific
SBOM release assets. Epoch does not publish `latest`. Package-manager SDKs, raw
binary archives, OS installers, and Helm charts remain deferred.

## Highlights

- The new `epoch-observability` Rust crate owns strict W3C `traceparent`
  parsing, bounded tenant fingerprints, low-cardinality HTTP classification,
  request and stage histograms, deterministic Prometheus exposition, and recent
  p99 diagnosis contracts.
- The Rust node exposes health, metrics, and latency evidence on a dedicated
  internal listener. Routing, replication, and storage paths emit structured
  request correlation and optional OTLP/HTTP spans without publishing resource
  names in metric labels.
- The Go control plane exposes its own internal Go/process/request/reconciliation
  metrics and an authenticated latency-diagnosis API. It queries regional nodes
  with bounded failover, caps responses, hides backend URLs, and returns an
  explicit no-sample result when no node has evidence.
- The console adds the **Why slow?** workflow with a strict closed decoder.
  The public documentation includes configuration, scrape targets, dashboards,
  alerts, query examples, security boundaries, failure behavior, and end-to-end
  Go, Java, and Python context guidance.
- Redis, Kafka, and AMQP gateway requests now emit protocol metrics and spans
  and propagate valid W3C context into the native backend. Gateway metrics stay
  on an internal-only listener by default.
- The Kubernetes operator accepts `spec.observability.otlpEndpoint`, renders
  internal metrics services and scrape annotations, and keeps metrics ports out
  of the public service. Compose carries the corresponding node, control, and
  gateway settings.
- OpenTelemetry Collector, Prometheus alert rules, and a Grafana dashboard are
  checked-in, schema-validated deployment assets rather than prose-only examples.
- Go, Java, Python, and Rust reject malformed new event trace context before
  transport or state mutation. Existing persisted envelopes with historical
  opaque context still recover; managed delivery omits that invalid legacy
  value instead of forwarding it.

## Upgrade and configuration

No storage-format migration is required. Existing durable snapshots remain
readable. All new observability listeners default to loopback/internal scope;
keep them private or place them behind an authenticated monitoring boundary.

Set an OTLP base endpoint only when a collector is available. Endpoint
validation rejects embedded credentials, paths, queries, and fragments; Epoch
resolves the trace export path itself. Tenant fingerprints are stable bounded
identifiers for metrics correlation, not cryptographic anonymization, and must
not be treated as secrets.

Review the operator CRD before enabling export, then apply the provided
collector, alert, and dashboard assets from `deploy/observability`. The
authenticated **Why slow?** path requires the same managed bearer-token boundary
as the other control APIs.

## Install and try

Resolve and verify immutable digests before use. For a source evaluation:

```shell
git clone https://github.com/Ripan-Roy/epoch.git
cd epoch
git checkout v0.2.0-beta.7
docker compose -f deploy/compose/docker-compose.regional.yml up --build
```

Configure metrics and trace export by following the tagged observability guide.
Use the public SDK pages for exact Go, Java, and Python regional examples; the
published quickstarts execute in CI from the same source shown to readers.

## Beta limitations

- Diagnosis currently attributes recent p99 evidence only to routing,
  replication, or storage. Quota, hot-partition, target-delivery, and client
  causes are reserved but not emitted without measurement.
- Exhaustive per-profile state metrics, support bundles, the **Can I lose
  data?** workflow, consumer/replay operational views, automated telemetry
  retention evidence, and production load/fault/SLO proof remain open.
- OTLP export is optional and intentionally lossy under collector failure;
  telemetry backpressure never becomes data-plane durability.
- Redis, Kafka, and RabbitMQ support remains the documented exact subset rather
  than full broker parity. Listener-side TLS and broader protocol semantics are
  still separate work.
- The release publishes five signed OCI manifests and source. Package-manager
  publication remains deferred until the SDK compatibility and credentialed
  registry gates are completed.
