# Epoch v0.2.0-beta.10

Epoch beta.10 adds one consistent workload-identity and authorization-audit
boundary to the Go control plane and Rust regional data plane. Existing
fingerprinted development credentials remain compatible, while production
callers can present bounded, short-lived Ed25519 OIDC access tokens. Every
authentication failure and authorization decision is durably hash-chained
before protected allowed work continues.

This remains a private-beta evaluation release. OIDC keys are statically
pinned, and the audit journals are tamper-evident local files rather than a
centralized externally immutable archive.

binary archives, OS installers, and Helm charts remain deferred.

## Identity highlights

- Policy format v2 accepts optional fingerprinted break-glass principals,
  OIDC configuration, or both. Policy v1 remains readable without migration.
- Go and Rust reject unknown or duplicate policy fields and apply the same
  bounded action and organization/project/environment/namespace scope model.
- Compact JWT access tokens must use `alg=EdDSA` and an exact configured `kid`
  backed by a pinned OKP/Ed25519 public JWK.
- Exact HTTPS issuer and accepted audience, canonical integer `iat`, optional
  `nbf`, `exp`, maximum lifetime, bounded clock skew, stable `sub`, unique
  `jti`, configured roles, and all four scope claims are required.
- Actions come only from the policy role map. Unknown algorithms, keys, roles,
  ambiguous JSON/base64url, invalid times, and SHA-256-revoked token IDs fail
  closed.
- Audit records retain an anonymized issuer/subject principal and credential
  class but have no field for the bearer token or token ID.

## Durable authorization audit

- Go and each Rust node own a separate canonical NDJSON journal with decimal
  sequence, previous digest, bounded decision event, and record digest.
- Every accepted event is appended and fsynced before an allowed protected
  operation continues. Authentication failures and authorization denies are
  also retained.
- Startup and every export verify the complete SHA-256 chain. A write or
  detected integrity failure becomes sticky and later protected work returns
  unavailable.
- `GET /v1/audit/events` exports the Go control journal and
  `GET /v1/admin/audit/events` exports one Rust node journal. Both require the
  distinct `audit.read` action, audit the export access, enforce strict
  1–1,000-record pagination, and filter records by tenant scope.
- Compose stores `/var/lib/epoch/audit.ndjson` on each node volume. The operator
  additionally stores `/var/lib/epoch-control/audit.ndjson` on the control PVC.

## Upgrade and configuration

No Catalog, Raft, EPRS, profile snapshot, Protobuf, or customer-data migration
is required. Existing v1 policy files continue to work. Both processes now
need writable durable audit storage and fail startup if an existing journal is
invalid or too broadly permissioned.

For OIDC, start from `spec/auth/identity-policy-v2.example.json`, replace its
issuer, audiences, role mapping, scope-claim names, and public JWKs, then mount
the same reviewed policy into Go and Rust:

```shell
EPOCH_AUTH_POLICY_PATH=/secure/epoch/identity-policy-v2.json \
EPOCH_AUDIT_PATH=/var/lib/epoch/audit.ndjson \
epoch-node --regional-config /secure/epoch/regional.json \
  --data-dir /var/lib/epoch

EPOCH_AUTH_POLICY_PATH=/secure/epoch/identity-policy-v2.json \
EPOCH_CONTROL_AUDIT_PATH=/var/lib/epoch-control/audit.ndjson \
EPOCH_CONTROL_STATE_PATH=/var/lib/epoch-control/registry.db \
epoch-control
```

Overlap old and new public keys during rotation and restart the processes after
changing policy. Back up and monitor journal capacity according to the same
durability expectations as the owning process data volume.

## Beta limitations

- Remote OIDC discovery and JWKS refresh, RSA/ECDSA algorithms, interactive
  authorization-code/token exchange, mTLS subject-to-role mapping, certificate
  issuance/revocation, hot policy reload, and replicated policy/ACL authority
  are not implemented.
- The bounded revoked-token-ID list is an emergency static control loaded at
  startup, not an online session or token-revocation service.
- Journals are separately ordered per process. Epoch does not yet merge them
  into one global history, enforce retention/legal hold, sign export bundles,
  or acknowledge delivery to an external WORM store.
- Authorization events do not yet cover every policy/configuration/key change,
  repair, backup lifecycle, replay/redrive, payload read, or connector action
  required by the final sensitive-operation matrix.
- Production penetration review, security operations, sustained audit-volume
  load, disk-exhaustion drills, and published security/SLO evidence remain
  release-readiness gates.
