# Epoch v0.2.0-beta.4

Epoch beta.4 makes Event Bus schemas an executable contract rather than a
structural hint. Avro, JSON Schema, and Protobuf definitions are compiled at
registration, drive payload validation, determine adjacent-revision
compatibility, survive replicated recovery, and are exposed through typed Go,
Java, and Python lifecycle APIs.

The release remains a private-beta evaluation build. It strengthens one
complete vertical feature without claiming production protocol compatibility,
a hosted-service SLO, or GA operating evidence.

## Published artifacts

The verified tag workflow publishes these exact multi-platform OCI manifests
for `linux/amd64` and `linux/arm64`:

- `ghcr.io/ripan-roy/epoch-node:v0.2.0-beta.4`
- `ghcr.io/ripan-roy/epoch-control:v0.2.0-beta.4`
- `ghcr.io/ripan-roy/epoch-operator:v0.2.0-beta.4`
- `ghcr.io/ripan-roy/epoch-cli:v0.2.0-beta.4`

Each exact-tag manifest is assembled from immutable native-runner digests,
inspected as non-root, signed keylessly with Sigstore, and accompanied by
BuildKit/GitHub provenance plus separate SPDX SBOM attestations and release
assets for both platforms. Epoch does not publish `latest`. Package-manager
SDKs, raw binary archives, OS installers, and Helm charts remain deferred.

## Highlights

- Apache Avro parses stored definitions, validates JSON-shaped payloads through
  Avro resolution, and checks backward, forward, or full reader/writer
  compatibility.
- JSON Schema performs meta-schema validation, compiles payload validators with
  bounded regular expressions and format checks, and applies conservative
  fail-closed object-shape compatibility.
- Self-contained proto2/proto3 definitions compile into descriptors and validate
  canonical Protobuf JSON. Definitions with multiple top-level messages select
  an explicit `root_message`.
- Immutable monotonic revisions bind exact `name@revision` references to
  event-type policies. Producer validation is linearizable read-only advice;
  broker validation is a deterministic committed publish outcome.
- Rejection details are capped, masked, and tested not to reflect payload values
  across all three formats.
- Go, Java, and Python expose typed registration, policy upsert/removal, explicit
  validation, and publish examples. The displayed regional quickstarts compile
  from the same sources shown on the documentation site.
- Deterministic compiler/compatibility tests and a real three-voter route prove
  registration, validation, committed rejection, convergence, and recovery.

## Compatibility and migration

Existing Event Bus commands and snapshots remain readable. `root_message` is an
additive optional field and is omitted from legacy encodings when absent. The
older `fields` overlay is retained for recovered v1 integration snapshots, but
new SDK registrations derive their contract from the official schema
definition and do not require it.

Schema compatibility is checked between adjacent immutable revisions. Clients
should register a new revision, explicitly validate representative producer
payloads, update the policy to the exact new reference, and only then deploy
writers. A broker-enforced rejection is committed and replayable; it is not
reported as a definitely-uncommitted transport failure.

## Install and try

Resolve and verify immutable digests before use; do not deploy a tag alone as
the final trust decision.

```shell
git clone https://github.com/Ripan-Roy/epoch.git
cd epoch
git checkout v0.2.0-beta.4
make bootstrap-check
make check
make kubernetes-config
```

Then follow the Event Bus SDK guide on the published documentation site to
register a schema, bind producer-and-broker validation, validate explicitly,
and publish with an exact schema reference.

## Beta limitations

- External JSON Schema references and Protobuf imports are rejected to keep
  compilation deterministic and free of network or file access.
- JSON Schema compatibility does not claim a complete formal implication
  solver; references and advanced composition forms fail closed.
- Per-schema administration beyond namespace authorization, generated schema
  classes, and public package-manager SDKs remain open.
- No RESP3, Kafka broker, AMQP, or MQTT compatibility gateway is claimed.
- Multi-region promotion/failback, production CSI behavior, mixed-version
  certification, measured RPO/RTO, and the required 30-day operating campaign
  remain separate gates.
