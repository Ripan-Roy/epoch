# Epoch v0.2.0-beta.1

> **Publication aborted:** the tag workflow stopped while compiling the arm64
> node image, so no curated GitHub prerelease was published. The immutable tag
> was not moved. Use `v0.2.0-beta.3` after its verified publication instead of
> consuming beta.1's partial registry artifacts.

Epoch's first beta prerelease closes the alpha operational boundary as one
vertical feature: secure managed transport, portable encrypted recovery,
learner-first membership changes, guarded Kubernetes upgrades, production
source-adapter foundations, signed fault evidence, and verifiable OCI images.

Beta means the complete native Epoch surface can now be installed and exercised
end to end in an existing Kubernetes development or evaluation environment. It
does not mean GA compatibility, a hosted-service SLO, or unattended production
certification.

## Published artifacts

The tag workflow publishes exactly these multi-platform OCI manifests for
`linux/amd64` and `linux/arm64`:

- `ghcr.io/ripan-roy/epoch-node:v0.2.0-beta.1`
- `ghcr.io/ripan-roy/epoch-control:v0.2.0-beta.1`
- `ghcr.io/ripan-roy/epoch-operator:v0.2.0-beta.1`
- `ghcr.io/ripan-roy/epoch-cli:v0.2.0-beta.1`

Every manifest is built from the exact current `main` tag, inspected as
non-root, signed keylessly with Sigstore, and accompanied by GitHub build
provenance plus separate SPDX SBOM attestations and downloadable SBOM assets for
each platform. Epoch does not publish `latest`. GitHub source archives remain
available; package-manager SDKs, raw binary archives, OS installers, and Helm
charts are intentionally deferred.

## Highlights

- TLS protects public HTTP and gRPC. mTLS protects peer and control-to-data
  traffic with verified DNS identity, fail-closed certificate loading, and
  independent bearer authorization. Go, Java, Python, and the CLI accept custom
  trust roots and optional client identity.
- A versioned regional semantic backup captures Catalog and every native tablet,
  authenticates checksums and identities, encrypts the object with AES-256-GCM,
  and restores only into a validated fresh destination. The operator schedules
  non-overlapping backups and records bounded receipts.
- Catalog and Raft now persist three- or five-voter membership. Replacement adds
  a learner, refreshes a membership-bearing snapshot after compaction, waits for
  catch-up, commits joint consensus, removes the old voter, and reopens from the
  finalized set.
- Image changes use a backup-freshness gate and serialized
  preflight/drain/update/postflight state machine. The beta acceptance campaign
  proves same-binary tag rollout behavior; mixed-version compatibility is still
  withheld.
- Event Bus source ingestion now shares one bounded leader-owned adapter
  contract across HTTP/CloudEvents, immutable S3-compatible/Azure/GCS objects,
  PostgreSQL logical replication, MySQL row binlogs, and Kafka consumer groups.
  Applied/error-routed records commit before the replicated source cursor;
  PostgreSQL feedback and Kafka offsets follow Epoch's checkpoint.
- The resumable four-profile fault runner binds source, image, platform, plan,
  logs, and results into SHA-256 receipts and an Ed25519-signed canonical
  manifest. Accelerated CI proves the harness without claiming the separate
  30-day operating gate.
- A clean one-control/four-worker Kind campaign proves mTLS install, all-profile
  traffic, encrypted backup, compacted-log voter replacement, backup-gated
  rollout, fresh-cluster restore, exact digest equality, and continued writes.

## Install and try

Resolve and verify immutable digests before use; do not deploy a tag alone as
the final trust decision. The complete signature, attestation, and SBOM commands
are in the [release artifact guide](../RELEASE_ARTIFACTS.md).

```shell
git clone https://github.com/Ripan-Roy/epoch.git
cd epoch
git checkout v0.2.0-beta.1
make bootstrap-check
make check
make kubernetes-config
```

Then follow [Kubernetes installation](../KUBERNETES_OPERATOR.md), [management
CLI](../CLI.md), and the end-to-end Go, Java, and Python guides for
[Stream](../REGIONAL_STREAM_SDK.md), [Queue](../REGIONAL_QUEUE_SDK.md),
[Cache](../REGIONAL_CACHE_SDK.md), and [Event Bus](../REGIONAL_EVENT_BUS_SDK.md).

## Compatibility and upgrade notes

- Persisted formats evolve additively from alpha.10. Catalog membership and
  profile snapshots have explicit versions and reject malformed, oversized, or
  identity-conflicting input before mutation.
- The Kubernetes API remains `platform.epoch.dev/v1alpha1`. Back up and verify
  the cluster before changing images. Do not infer mixed-version safety from the
  same-binary beta acceptance rollout.
- Native SDK APIs remain provisional and repository-local. Applications should
  pin this exact release and use idempotency/fencing fields as documented.
- Existing alpha source deployments should use a fresh beta cluster plus the
  supported semantic backup/restore path; direct journal copying is not an
  upgrade or migration contract.

## Beta limitations

- No RESP3, Kafka broker, AMQP, or MQTT compatibility gateway is claimed; the
  named source adapters do not turn Epoch into those brokers.
- No multi-region promotion/failback, arbitrary voter count, automatic general
  rebalance, cloud workload-identity certification, or private connector
  networking is included.
- The Kubernetes proof uses local Kind storage and a same-binary two-tag
  rollout. Production CSI behavior, mixed-version compatibility, measured
  RPO/RTO, and cross-zone failure remain separate gates.
- The accelerated fault campaign is not the required 30-day active-runtime
  campaign and establishes no throughput, latency, availability, or hosted SLO.
- Package-manager publication, raw signed binaries, OS installers, and Helm
  packaging remain intentionally deferred.
