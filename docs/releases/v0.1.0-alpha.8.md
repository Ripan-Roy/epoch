# Epoch v0.1.0-alpha.8

Epoch's eighth source prerelease completes the Work Queue development surface
through `QUEUE-015`. It adds one bounded replicated state-services layer,
crash-safe Queue-to-Queue dead-letter forwarding, and the same complete
lifecycle in Go, Java, Python, HTTP, and the public documentation. This remains
a fixed-voter engineering alpha, not a production scale or availability claim.

## Source preview and license

The repository source is available under the MIT License. GitHub provides ZIP
and tar.gz archives of the tagged tree; those source archives are the only
release downloads. This release publishes no binaries, container images,
installers, SDK packages, or package-registry artifacts.

## Highlights

- Queue admission enforces exact message-count and optional active-byte limits
  with explicit reject-new, drop-oldest, or dead-letter-oldest overflow. Active
  leases are never stolen and dedupe resolves before eviction.
- Durable idle expiry, message TTL/max-age, scheduling, retry, and session-lock
  deadlines share one committed-time maintenance model.
- FIFO session/message groups use one renewable exclusive token bound to Queue
  incarnation, committed term, consumer epoch, generation, and deadline.
- Deterministic priority aging prevents permanent low-band starvation. A
  replicated token bucket, Queue-wide live-delivery ceiling, and circuit breaker
  gate downstream dispatch.
- Consumers can defer a fenced delivery and later receive that exact message
  ID. Correlation and reply-destination metadata survive voter snapshots and
  are available through linearizable reads.
- A `quorum_durable` Queue may forward dead letters to another Queue in the same
  namespace. The source outbox pins the exact target incarnation, commits a
  stable history-derived target enqueue, and records source completion only
  after the target receipt commits.
- Go, Java, and Python expose session acquire/renew/release, advanced enqueue,
  defer/exact receive, advanced status, correlation, and DLQ outbox reads. The
  public quickstarts execute the complete lifecycle.

## Compatibility and upgrade notes

- Canonical Queue command v3 is additive. Command v1 and v2 bytes remain
  readable and their golden vectors remain unchanged.
- Queue engine snapshot v2 and Queue tablet snapshot v2 add advanced state and
  the durable forwarding outbox. Valid v1 snapshots reopen with empty/default
  advanced state.
- The legacy v1 Queue recovery checksum remains unchanged when advanced state is
  absent. Configured advanced state participates in the complete checksum and
  tablet digest.
- Do not downgrade a live tablet after command-v3 state or a bound DLQ outbox
  entry has committed.
- Go, Java, and Python APIs remain repository-local and provisional. Package
  publication is intentionally deferred.

## Alpha limitations

- One Queue resource is one physical partition. There is no native
  bidirectional receive stream, automatic prefetch, or multi-partition session
  coordinator.
- FIFO means commit-order selection under one exclusive session owner. It is not
  a cross-session global ordering or application-side serial-execution claim.
- Temporary replies are normal managed Queues with idle expiry. Request/reply
  and DLQ forwarding are not distributed transactions or exactly-once external
  side effects.
- DLQ forwarding targets only a distinct `quorum_durable` materialized Queue in
  the same namespace; self-targeting and non-quorum targets are rejected.
  External brokers, object stores, and custom executors remain open.
- Dynamic membership, production identity/TLS/OIDC/mTLS, generated response
  models, timer/throughput/fairness SLOs, fuzz/soak/scale evidence, and the
  exhaustive production fault matrix remain open.
- No Cargo crate, public Go module, Maven artifact, Python distribution, npm
  package, OCI image, installer, signed binary, SBOM, or provenance statement
  is released from this tag.
