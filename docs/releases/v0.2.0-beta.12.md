# Epoch v0.2.0-beta.12

Release candidate; not yet tagged or published. Beta.11 remains the published
release. An earlier beta.12 release-commit
[main CI](https://github.com/Ripan-Roy/epoch/actions/runs/37189330373) failed
Stream follower recovery in Container/Compose while its other ten jobs passed.
The subsequent hardening merged in PR #149 at `d8adf75`; its
[exact-main CI](https://github.com/Ripan-Roy/epoch/actions/runs/37353098801)
passed all 14 jobs and
[Pages](https://github.com/Ripan-Roy/epoch/actions/runs/37353099031) passed.
The complete native three/five-controller artifact independently verifies.
Public-SDK Catalog certification and the final exact-release/tag gates remain
required before this release or its OCI artifacts may be published.

Epoch beta.12 moves managed regional metadata into the replicated Rust Catalog
and makes the Go control plane replaceable. Three control replicas share one
lease-fenced reconciler authority rather than a writable local metadata file.
The release adds atomic managed lifecycle commands, durable operation lookup,
resumable authorized changes, and bounded checkpoint-capacity recovery.

This remains a private-beta evaluation release for QA and controlled test
environments. It is not a declaration of general production readiness.

## Replicated management and ownership

- Managed desired documents, observed status, live/tombstoned generations,
  public request outcomes, and change history commit in Catalog consensus.
  Managed reads cross a leader `ReadIndex` barrier.
- One replicated lease with a monotonic fence owns periodic reconciliation.
  Stale owners cannot publish status, reserve placement, plan membership, or
  delete after ownership changes. Standbys do not challenge a live owner.
- Capacity admission and initial materialization commit atomically. Managed
  deletion removes desired and native state in one fenced command, deriving
  native generation inside the transition rather than from lagging status.
  Public deletes may enter through any control replica without sticky routing.
- Reconciliation and membership retry identities bind the complete lease and
  capacity evidence. Exact ambiguous attempts replay; refreshed capacity may
  recover from an earlier rejection with a distinct attempt identity.
- The operator renders three ordered, host-anti-affined control replicas,
  pod-derived instance labels, readiness at two replicas, and a
  `minAvailable: 2` disruption budget. Each control process derives a fresh
  random 128-bit incarnation owner from its label; a restarted or overlapping
  replacement cannot adopt its predecessor's unexpired lease. Startup fails
  closed if the required entropy is unavailable.
- Fully qualified HTTP item GET/DELETE routes preserve exact tenant scope,
  authorization, and managed deletion; legacy three-segment routes remain.
  Completed delete replay resolves its original token before checking a
  recreated resource's generation. Omitted, explicit zero, and nonzero caller
  preconditions remain distinct, and an old exact replay cannot delete the new
  incarnation.

## Administrative contract and bounded recovery

- Generated RegionalAdmin gRPC adds atomic batches of 1–128 desired resources,
  exact affected-resource-authorized `GetOperation`, and resumable
  `WatchResourceChanges`. Operation metadata retains the command kind and the
  original optional delete precondition, including absent versus explicit zero.
- Inventory uses canonical keyset pages of at most 128 resources and 768 KiB,
  with one stable Catalog high-water cursor. Change history retains at most
  4,096 entries and expires earlier against the complete checkpoint byte budget.
  Cursor zero becomes stale after the retained prefix advances; resynchronize
  from a linearizable inventory snapshot instead of silently skipping events.
- Native Catalog application checkpoint v2 stores raw bytes below the 4 MiB
  consensus envelope, reserves header space, and omits duplicate retry payloads.
  Existing v1 JSON/base64 checkpoints remain readable. Go bounds authority
  responses at 5 MiB, including JSON/envelope allowance.
- Snapshot-capacity rejection is a committed non-mutating result, not an
  applier failure. Snapshot v8 compacts refusals into durable token/command
  digest bindings with bounded authorization and operation metadata, then seals
  growth. Only real deletes that strictly shrink the full snapshot may commit
  during this recoverable seal. Ordinary writes resume after the rejection
  reserve is restored; recovered v9 keeps replay/conflict/lookup identity even
  after consensus compaction.
- If the compact rejection ledger itself fills, snapshot v10 terminally rejects
  all mutation, including cleanup, until migration. Mutable sealed snapshots
  reserve the extra serialized byte needed for this marker. Sealing preserves
  correctness; it is not a substitute for horizontal Catalog capacity.

## Idle-voter recovery hardening

Bounded peer HTTP send exhaustion and queue drops now report correlated
outcomes to the Raft actor. Snapshot callbacks bind the exact process
incarnation, scope, leader term, snapshot index, and attempt; stale callbacks
cannot alter a later leader's work. An idle voter can retry a lost latest
snapshot without another application write or checkpoint. Transport success
is never a quorum acknowledgement. Learner catch-up refreshes a compacted
baseline when still needed, including committed membership state. Weak worker
feedback channels prevent actor ownership cycles on shutdown. These changes
do not introduce a new application command or checkpoint format.

## Upgrade and migration

Back up and inspect the existing regional data and legacy control registry
before upgrading. Upgrade data nodes to a build that understands the new
Catalog command/snapshot formats before starting the new control plane. Existing
Catalog v6 commands/snapshots and native checkpoint v1 images remain readable;
new managed-delete commands use v7 and capacity states may write v8–v10. Do not
assume an older binary can read these new formats or perform an in-place
downgrade. Mixed-version rollback certification remains open.

For an existing single-control StatefulSet, the operator updates and verifies
ordinal zero before scaling to three. Ordinal zero atomically imports one
consistent legacy bbolt image into an empty Catalog. The import accepts at most
4,096 live/tombstoned generation records within the 512 KiB command and 4 MiB
native checkpoint envelope; larger inputs fail closed pending a migration tool.
Unqualified legacy-local keys map deterministically to
`epoch-legacy/local/default`; mapped collisions fail before mutation.

Retain the old bbolt file as rollback evidence. Its historical idempotency
ledger is not imported because it lacks the new canonical command identity.
Resolve ambiguous pre-migration requests by inspecting resource generations;
do not blindly replay old tokens. Give each control instance a unique
`EPOCH_CONTROL_INSTANCE_ID`. The legacy-state path is import-only; it is no
longer acknowledgement authority. See the
[operator migration guide](https://github.com/Ripan-Roy/epoch/blob/v0.2.0-beta.12/docs/KUBERNETES_OPERATOR.md).

## Remaining production gates

Broader production multi-control chaos and long-duration lease-clock evidence,
horizontal Catalog capacity/sharding and terminal-seal migration, public
operation-retention guarantees, and legacy token-history migration remain open.
Full production security/rotation certification, mixed-version rollback,
external immutable audit retention, matched performance/SLO evidence, disaster
recovery drills, and the elapsed 30-day soak are not claimed.
The separate SDK contract candidate passes full-package strict Python typing
and response-shape validation locally. Complete public-SDK Catalog failure
certification, protected delivery, persistent native streaming, and the full
contract/version matrix remain open; executable quickstarts alone do not close
those gates.

Redis, Kafka, and RabbitMQ retain the bounded beta.11 compatibility surface;
this release does not add full broker parity. Geo failover/failback, production
cloud CSI/topology attestation, managed autoscaling, billing, and private
networking also remain outside this release.
