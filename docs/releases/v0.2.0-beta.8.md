# Epoch v0.2.0-beta.8

Epoch beta.8 deepens the private-beta Redis, Kafka, and RabbitMQ migration
surface while keeping every compatibility boundary explicit. Redis multi-set
is now atomic, Kafka classic groups accept a bounded static identity, and AMQP
adds headers routing plus durable native dead-letter forwarding.

This remains an evaluation release, not a claim of full Redis, Kafka, or
RabbitMQ parity. The supported wire/API subset is the allowlist in the tagged
protocol-compatibility guide.

## Highlights

- Redis `MSET` and `MSETNX` normalize at most 128 distinct UTF-8 keys and use
  one revision-fenced native Cache transaction. A successful command writes
  every key, and a failed `MSETNX` writes none. Repeated command keys retain
  Redis final-value-wins behavior.
- Kafka Java clients may provide a bounded `group.instance.id` to the
  implemented classic `consumer`/`range` group path. The identity survives
  gateway replacement and is checked during join, sync, heartbeat, offset
  commit, and leave.
- AMQP 0-9-1 supports process-shared direct, fanout, topic, and headers
  exchanges. Headers bindings use bounded string criteria with an explicit
  `x-match=all|any` mode.
- A Queue declaration may name the default dead-letter exchange and a routing
  key exactly matching its provisioned native `advanced.dead_letter_target`.
  Reject or nack without requeue uses the replicated Queue outbox rather than
  a lossy gateway republish.
- AMQP-origin dead letters drop their old TTL/expiration, target the destination
  Queue through the default exchange, and carry bounded
  `x-first-death-exchange`, `x-first-death-queue`, and
  `x-first-death-reason` string headers.
- Queue restart validation accepts both newly transformed forward envelopes
  and pending legacy pre-transformation envelopes, preventing an upgrade from
  stranding existing dead-letter state.
- Deterministic malformed-input corpora exercise RESP requests, Kafka record
  bodies, and framed AMQP input in the ordinary Rust test suite. They supplement
  rather than replace coverage-guided fuzzing.
- The public Pages guide, migration scanner, compatibility matrix, PRD ledger,
  delivery checklist, testing contract, and ADR-0046 describe the implemented
  behavior and its non-claims.

## Upgrade and configuration

No storage-format migration is required. Existing Queue snapshots remain
readable, including pending dead-letter forwards created before beta.8.

Redis clients using `MSET` gain a stronger all-or-nothing boundary. Under
repeated concurrent shard changes, the gateway returns a bounded conflict
instead of exposing partial writes. `MSETNX` is now advertised by `COMMAND` and
the migration scanner.

Kafka static identity is deliberately narrower than full Kafka static
membership. Do not run simultaneous live consumers with the same
`group.instance.id`; beta.8 has no separate live-owner epoch to fence that
case. Multi-topic, regex, cooperative, and the newer consumer-group protocols
remain unsupported.

For AMQP dead-lettering, provision the destination Epoch Queue first and set
the source Queue's native `advanced.dead_letter_target`. Client declarations
must use `x-dead-letter-exchange=""` and the exact configured destination as
`x-dead-letter-routing-key`. Named DLX routing and RabbitMQ `x-death` arrays are
not implemented. Exchange and binding topology remains gateway-process state
and must be redeclared after gateway replacement.

## Install and try

Resolve and verify immutable digests before use. For a source evaluation:

```shell
git clone https://github.com/Ripan-Roy/epoch.git
cd epoch
git checkout v0.2.0-beta.8
docker compose -f deploy/compose/docker-compose.regional.yml up --build
```

Follow the tagged protocol-compatibility guide for exact Redis, Kafka, and
RabbitMQ client configuration. The public Go, Java, and Python quickstarts are
compiled or executed in CI from the same source shown on Pages.

## Beta limitations

- Redis transactions/scripts, Pub/Sub/Streams compatibility, cluster mode,
  binary collection members/keys, and broader differential conformance remain
  outside this gateway subset.
- Kafka simultaneous duplicate-static-owner fencing, multi-topic/regex
  subscriptions, cooperative/new consumer groups, idempotent or transactional
  producers, admin mutations, SASL, and ACL APIs remain unsupported.
- AMQP durable topology, named-DLX routing, full field-table matching,
  `x-death`, transactions, AMQP 1.0, and listener-side TLS remain open.
- Coverage-guided fuzz certification, matched Redis/Kafka/RabbitMQ performance
  reports, production SLO evidence, and design-partner cutover/rollback drills
  are still required before the compatibility milestone is complete.
- The release publishes five signed OCI manifests and source. Package-manager
  publication remains deferred until the SDK compatibility and credentialed
  registry gates are completed.
